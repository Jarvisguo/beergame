# 啤酒游戏玩家指南

玩家版 · 更新日期：2026-10-30

四人协作经营一条供应链，在 26 周内体验库存、交货延迟与需求波动。

**玩家入口：https://beergame.zeabur.app/**

## 01 游戏目标与角色

你每周决定向上游订多少箱啤酒，尽量满足下游需求，同时控制库存和积压。团队目标是让 26 周的累计总成本尽可能低。

| 你的角色 | 向谁订货 | 向谁交货 |
| --- | --- | --- |
| 零售商 | 批发商 | 客户 |
| 批发商 | 区域仓库 | 零售商 |
| 区域仓库 | 工厂 | 批发商 |
| 工厂 | 工厂生产线 | 区域仓库 |

货物由工厂流向客户；订单沿相反方向传递。工厂提交的订单对应生产补货。

## 02 加入游戏

1. 等待游戏启动，打开玩家入口，输入不超过 15 个字符、与其他在线玩家不同的用户名，点击“开始”。
2. 系统自动分配小组和角色。页面顶部显示“第 X 组”、你的角色和用户名；请记住这三项信息，断线后继续使用原用户名。
3. 本组凑满四个角色后进入第 1 周。每组独立推进；如有 AI 补位，请按本次游戏安排进行。

## 03 关键参数

| 参数 | 本游戏设定 |
| --- | --- |
| 游戏周期 | 26 周；完成第 26 周结算才算完成整局。 |
| 每周订货 | 0 至 100 箱的整数；提交后本周不能修改。 |
| 初始库存与积压 | 每个角色库存 12 箱，积压 0 箱。 |
| 初始在途 | 角色间订单队列初始为 1 期、4 箱；货运或工厂生产队列为 2 期、每期 4 箱。 |
| 订单提前期 | 本周向上游发出的订单，上游在下一周收到。 |
| 物流／生产提前期 | 上游本周发出的货物约 2 周后到达；工厂生产补货也经过 2 周队列。 |
| 每周成本 | 结算后库存每箱 0.5，结算后积压每箱 1，逐周累计。 |
| 客户需求 | 可设为混合、增长或下降趋势，以本次游戏设置为准。 |

# 每周操作与断线恢复

每周每个角色提交一次订单；本组四个角色均提交后统一结算。

## 04 每周怎样操作

1. **看结果。** 查看当前周次、库存、积压、收到的下游订单，以及上一轮到货和发货结果。
2. **决定订货。** 结合需求与已下单但尚未到货的数量，在订货框输入 0 至 100 的整数，点击“提交订单”。暂时不需要补货也应提交 0，不能跳过本周。
3. **等待队友。** 页面会提示尚未下单的角色；四个角色都提交后，本组自动结算并进入下一周。提交成功后不能重复修改本周订单。
4. **完成整局。** 重复操作至第 26 周结算完成。此后停止接受新订单，再结合经营报告复盘。

**看懂提前期：** 假设你第 5 周下单，上游第 6 周收到；若上游第 6 周即可发货，你约在第 8 周收到。若上游缺货，等待可能更久，因此不能把“1 周订单延迟 + 2 周物流延迟”理解为每次下单都固定 3 周全部到货。系统自动处理收货、发货和积压。

## 05 看懂经营指标

| 指标 | 含义 |
| --- | --- |
| 库存 | 当前持有、尚未发出的货物；库存过多增加持有成本。 |
| 积压 | 下游尚未满足的订单；以后仍需补发，不会自动消失。 |
| 累计成本 | 每周库存和积压成本的累计值，是评价经营表现的重要依据。 |
| 牛鞭效应 | 比较自己发出的订单与收到的需求的波动，详见下一页。 |

每周成本 = 结算后库存 × 0.5 + 结算后积压 × 1。例如库存 0 箱、积压 4 箱，本周成本为 4。

## 06 切换应用、锁屏或断线后

1. 切到其他应用不一定立刻断线，但手机可能暂停后台网页。返回游戏后，页面会自动尝试重新连接并恢复原身份。
2. 若没有恢复，点击“重新连接并恢复游戏”；如回到登录页，输入**原用户名**。不要为重连随意更换用户名。
3. 从服务器确认断线时起，默认保留座位 **10 分钟**。保留期内恢复原小组、角色、游戏进度和已经提交的订单；该时间不是后台网络连接的保证时间。
4. 超过 10 分钟，座位可能释放，无法保证回到原位。若仍无法恢复，请联系游戏组织者。组织者移除玩家、重置游戏或服务重启后，原状态也可能无法恢复。

**等待不动时：** 先看尚未下单的角色，提醒队友完成提交。不要因暂时缺货反复大幅加单，先考虑订单和货物的在途时间。

# 读懂牛鞭效应与经营报告

页面显示具体放大倍数及五档等级，数值不封顶。

## 07 方差放大倍数 B

**B = 你的订货量方差 ÷ 你收到的下游需求量方差。** 方差衡量一组数量的波动程度；零售商以客户需求为基准，其他角色以实际收到的下游订单为基准，不把历史积压重复算作新需求。

例如，订货标准差为 4 箱，需求标准差为 2 箱，则 B = 4² ÷ 2² = 4.00 倍。这里说的是**方差放大 4 倍**，不是订货数量增加 4 倍。

| 放大倍数 B | 页面等级 |
| --- | --- |
| 0 ≤ B ≤ 1 | 未放大 |
| 1 < B ≤ 2 | 轻度放大 |
| 2 < B ≤ 4 | 中度放大 |
| 4 < B ≤ 8 | 高度放大 |
| B > 8 | 极高放大 |

以上是本游戏的课堂展示分档，不是行业统一标准。例如“6.40× · 高度放大”，表示订单方差为收到需求方差的 6.40 倍。

## 08 统计范围与特殊提示

每周结算后，累计统计第 1 周至最新已完成周；满 5 周后才分档。卡片会显示统计周数，并用订货标准差、需求标准差和订货范围帮助理解结果。

| 页面提示 | 怎样理解 |
| --- | --- |
| 样本积累中：3/5 周 | 只完成了 3 周，暂不分级。 |
| 需求与订货均无波动 | 两者都恒定，分母为零，不能计算倍数。 |
| 恒定需求下出现订单波动 | 收到的需求没变，但你的订单发生了波动；倍数显示“—”。 |
| 未发生订货 | 一直订 0 箱；低波动不代表需求已被满足。 |
| 数据不完整 | 记录不足，不能据此判断程度；不把缺失值当成 0。 |

**订货相对波动 CV** = 订货标准差 ÷ 订货均值。它只描述自己的订单变化，是辅助指标；CV 高不一定意味着把下游需求放大了。“未放大”也不等于经营优秀，要同时看成本、库存和积压。

## 09 游戏结束后的复盘

拿到经营报告后，先确认原小组号。报告只纳入完成全部 26 周的小组；未完成整局的小组不参与汇总和排名。

查看本环节倍数、相对最终客户需求的倍数，以及“收到需求与发出订单”曲线。趋势图展示的是**截至第 N 周的累计放大倍数**，不是某一周单独的分数。小组最大倍数会标明对应角色和可计算范围。

结合库存、积压与成本，回顾哪些订货决定导致后续库存或缺货变化。仅凭成本差异或某个倍数，不能直接断定具体原因。
